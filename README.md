# Протектор - демо-каталог б/у шин и дисков

Живой кейс для портфолио: мобильный сайт-каталог склада б/у шин и дисков в Екатеринбурге. Сверстан 1:1 по макетам ChatGPT (`ref/`), собирается из таблиц CSV в статический сайт одной командой.

**Демо онлайн:** https://vladosick-git.github.io/protektor-demo/
- посадочная: https://vladosick-git.github.io/protektor-demo/shiny/zimnie/205-55-r16/
- карточка: https://vladosick-git.github.io/protektor-demo/shiny/nokian-hakkapeliitta-10-205-55-r16-sh-1048/
- диски: https://vladosick-git.github.io/protektor-demo/diski/r17-5x114-3/

```
python build.py            # собрать в dist/
python build.py --serve    # собрать и открыть http://localhost:8080/protektor-demo/
```

Нужен Python 3.10+, для фото - `pip install pillow`. Сотруднику магазина - [Как обновить товары.md](Как%20обновить%20товары.md).

## Что внутри

| Путь | Что это |
|---|---|
| `data/tires.csv`, `data/wheels.csv` | ассортимент, одна строка = один комплект (источник правды) |
| `data/fitment.csv` | «Подойдут на»: размер шин и сверловка дисков -> модели авто |
| `data/published_urls.json` | все когда-либо опубликованные адреса, для 301 (пишет build.py) |
| `photos/<артикул>/` | фото комплекта, `01 Комплект.jpg`, `02 Колесо 1.jpg` ... |
| `config.json` | адрес сайта, контакты, номер Метрики, сроки брони и жизни проданных |
| `build.py` | генератор: страницы, sitemap, robots, редиректы, JSON для фильтров |
| `src/` | стили, скрипты (`app.js` - фильтры и формы, `metrika.js` - все цели), иконки |
| `tools/validate.py` | проверка JSON-LD по словарю schema.org, canonical, sitemap, robots, ссылок |
| `tools/test_site.js` | сценарии в Chrome: фильтры, переходы, бронь, цели, избранное, поиск |
| `tools/shot.js` | скриншоты (`check`, `kwork`, `og`); `screens/` - 5 картинок 1920x1280 для Кворка |
| `ТЗ_фото_для_GPT.md` | промпты на чистые фото вместо вырезок из макетов |

Демо-ассортимент: 115 шин и 38 дисков. Позиции с макетов на месте (Nokian Hakkapeliitta 10 за 28 400 ₽, проданный Pirelli Ice Zero 2, диски R17 5x114,3 и т.д.), остальное досоздано `tools/make_demo_data.py` с фиксированным seed. В 205/55 R16 зима ровно 38 комплектов в наличии с разбивкой по брендам как на макете.

## Страницы и SEO-структура

- `/` - главная: подбор по размеру (ширина, профиль, диаметр, сезон; вкладка дисков - диаметр, PCD, ET, ЦО), популярные размеры, свежие поступления.
- Посадочные генерируются из данных, у каждой свой title, description, h1 и текст с живыми цифрами (сколько в наличии, бренды, цены от-до, средний протектор, на какие авто):
  - `/shiny/`, `/shiny/zimnie/`, `/shiny/letnie/`, `/shiny/vsesezonnye/`
  - `/shiny/205-55-r16/` - размер во всех сезонах
  - `/shiny/zimnie/205-55-r16/` - сезон + размер
  - `/diski/`, `/diski/r17/`, `/diski/r17-5x114-3/`
- Товар: `/shiny/nokian-hakkapeliitta-10-205-55-r16-sh-1048/` (в адресе артикул, поэтому адрес не меняется при правке цены).
- Служебные: выкуп, шиномонтаж, доставка, колёса в сборе, контакты, политика (noindex), избранное и поиск (noindex), 404.

### Фильтры и индексация

Размер и сезон - это навигация: выбор в фильтре ведёт на чистый адрес посадочной. Остальные фильтры (бренд, тип, протектор, год, количество, цена, ET, ЦО...) работают на JS и пишутся в GET-параметры (`?brand=Michelin&tread=7`), чтобы ссылкой можно было поделиться. Такие адреса в индекс не пускаем:

- у каждой страницы `canonical` на чистый адрес;
- `robots.txt`: для всех `Disallow: /*?`, для Яндекса `Clean-param` по всем параметрам фильтров и utm - Яндекс склеит их с чистым адресом и не будет тратить обход;
- страницы поиска и избранного - `noindex`.

Первая страница выдачи отдаётся готовым HTML (карточки видны поисковику без JS), дальше JS. Все товары дополнительно лежат в `sitemap.xml` с картинками (`image:image`), поэтому пагинации в индексе не нужно.

Посадочная без товаров в наличии остаётся доступной (с формой «подобрать под заказ»), но получает `noindex,follow` и выпадает из sitemap, чтобы не плодить пустые страницы. Как только товар появится - вернётся в индекс сам.

### Разметка schema.org

- Товар: `Product` + `Offer` (цена, RUB, `itemCondition: UsedCondition`, `availability`: `InStock` / `Reserved` / `SoldOut`, количество, продавец), характеристики через `additionalProperty`.
- Все страницы: `BreadcrumbList`, совпадает с крошками на странице.
- Посадочные: `CollectionPage` + `ItemList` первой страницы.
- Главная и контакты: `TireShop` (адрес, координаты, часы, рейтинг).

`python tools/validate.py` проверяет все типы и свойства по актуальному словарю schema.org, обязательные поля Product для Google, совпадение `Offer.url` с canonical и `SoldOut` с плашкой «Продано», крошки, sitemap (нет noindex-страниц, все индексируемые на месте), robots.txt, битые ссылки, alt у картинок и дубли title.

## Проданные товары: политика

Б/у ассортимент меняется каждый день, а страницы товаров успевают попасть в индекс и собрать переходы. Поэтому:

1. **Продано (статус `продано` + дата).** Товар уходит из выдачи каталога и показывается в блоке «Недавно продано» на своей посадочной. Его страница остаётся с ответом 200 и в индексе: плашка «Продано», зачёркнутая цена, кнопки «Смотреть похожие» и «Подобрать под заказ», блок из трёх похожих в наличии, в разметке `availability: SoldOut`. Так человек из поиска не упирается в 404, а видит, что ассортимент живой, и уходит в похожие.
2. **Через 60 дней** (`sold_keep_days` в `config.json`) страница заменяется на 301 на посадочную «сезон + размер» (для дисков - «диаметр + PCD»). Если там пусто - на размер в другом сезоне, потом на сезон, потом на раздел. Из sitemap страница пропадает.
3. **Строку удалили из таблицы** - адрес не теряется: `data/published_urls.json` помнит все опубликованные адреса и строит для них тот же 301. Если поменялись бренд или модель (а значит адрес), старый адрес ведёт на новый по артикулу.

Где 301 берутся физически: для Apache - `dist/.htaccess`, для nginx - `deploy/nginx-redirects.conf` (include в `server {}`). На GitHub Pages серверных редиректов нет, поэтому там лежит страница-заглушка с `meta refresh 0`, `canonical` на цель и `noindex` - Яндекс и Google обрабатывают её как редирект.

Почему 60 дней: за это время поисковик переобходит страницу и видит `SoldOut`, а ссылка из выдачи, мессенджеров и Авито продолжает работать. Для сезонного товара срок можно увеличить до 90-120 дней, чтобы прошлогодние зимние страницы пережили межсезонье.

## Формы и Метрика

Формы: заявка (шапка и нижняя панель), бронь на 2 дня (из карточки и страницы товара), выкуп с загрузкой фото. Валидация телефона с маской и согласие на обработку данных. В демо ничего не отправляется, клики по телефону и мессенджерам показывают подсказку вместо перехода.

Все цели - в одном месте, `src/js/metrika.js`:

| Действие | Цель |
|---|---|
| клик по телефону | `click_phone` |
| WhatsApp / Telegram | `click_whatsapp` / `click_telegram` |
| заявка | `form_lead` |
| бронь | `form_bron` |
| выкуп | `form_vykup` |

Чтобы включить: номер счётчика в `config.json` -> `metrika_id`, код счётчика build.py вставит сам; в Метрике создать цели «JavaScript-событие» с этими идентификаторами. Подтверждение Вебмастера - `yandex_verification`. Для боевого сайта в формах нужно подключить отправку (Telegram-бот, почта или CRM) вместо демо-ответа - это одна функция в обработчике `submit` в `app.js`.

## Хостинг

Сейчас настроено под GitHub Pages: `site_url` = `https://vladosick-git.github.io/protektor-demo`, `base_path` = `/protektor-demo/`. Сборку и публикацию делает `.github/workflows/pages.yml`: правка CSV или фото в репозитории -> через минуту сайт обновлён. В настройках репозитория: Settings -> Pages -> Source: GitHub Actions.

На своём домене: `python build.py --site-url https://protektor-ekb.ru --base /` (или поменять в `config.json`), выложить `dist/`. robots.txt работает только в корне домена, поэтому на github.io-подпапке он показательный, а на своём домене - настоящий.

`today` в `config.json` зафиксирован на 2026-10-15, чтобы демо не «старело» (проданные не уезжали в 301). На боевом сайте строку надо удалить - тогда берётся текущая дата.
